# 5.6 Design Principles

## About
This topic introduces basic software design principles used to write clean, maintainable, and reusable code. These principles help organize code properly and reduce unnecessary complexity.

## Concepts Covered
* Single Responsibility Principle (SRP)
* Dependency Inversion Principle (DIP)
* DRY (Don't Repeat Yourself)
* Cohesion
* Coupling
* Pragmatic design patterns
* Clean and maintainable code

## What I Learned
* Single Responsibility means a class or module should have one clear responsibility.
* Dependency Inversion helps reduce direct dependency between different parts of a program.
* DRY means avoiding unnecessary repetition of code.
* High cohesion means related responsibilities stay together.
* Low coupling means components depend less on each other.
* Design patterns can provide practical solutions to common design problems.
* Good design should remain simple and should not add unnecessary complexity.

## Learning Outcomes
After completing this topic, I can:
* Apply the Single Responsibility Principle.
* Avoid repeated code using DRY.
* Understand dependency inversion.
* Identify high cohesion and low coupling.
* Organize code into smaller and clearer components.
* Use simple and practical design patterns when needed.
* Write cleaner and more maintainable Python programs.
