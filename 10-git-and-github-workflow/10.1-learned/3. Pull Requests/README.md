# 13.3 Pull Requests

## About
This topic introduces Pull Requests (PRs) in GitHub. It focuses on creating a PR, writing a clear description, responding to review comments, making requested changes, and understanding the merge process.

## Concepts Covered
* Pull Requests
* PR descriptions
* Review comments
* Requested changes
* Approvals
* Updating a PR
* Merge strategies
* Code review

## What I Learned
* A Pull Request is used to propose changes to a repository.
* A clear PR description explains what was changed and why.
* Review comments provide feedback on the code.
* Requested changes need to be addressed before merging when required.
* A PR can be updated by pushing new commits to the same branch.
* An approval indicates that a reviewer has reviewed the proposed changes.
* Merge strategies determine how changes are added to the main branch.
* Code review helps improve code quality and collaboration.

## Learning Outcomes

After completing this topic, I can:
* Create a Pull Request from a feature branch.
* Write a clear and useful PR description.
* Read and respond to review comments.
* Make changes requested by reviewers.
* Update an existing Pull Request.
* Understand approvals and merge strategies.
* Communicate professionally during code review.
