# 13.4 Issues

## About
This topic introduces GitHub Issues as a way to track requirements, tasks, bugs, and project work. It focuses on writing clear issues, defining acceptance criteria, breaking large tasks into smaller tasks, and adding useful implementation notes.

## Concepts Covered
* GitHub Issues
* Requirements
* Acceptance criteria
* Task decomposition
* Labels
* Implementation notes
* Issue organization
* Task tracking

## What I Learned
* An issue describes a specific task, requirement, or problem.
* Clear requirements explain what needs to be done.
* Acceptance criteria define when a task can be considered complete.
* Large tasks can be divided into smaller and manageable tasks.
* Labels help organize and categorize issues.
* Implementation notes provide useful technical details about the task.
* Well-written issues make project work easier to understand and track.

## Learning Outcomes

After completing this topic, I can:
* Create clear GitHub Issues.
* Write simple and specific requirements.
* Define acceptance criteria for a task.
* Break large tasks into smaller tasks.
* Use labels to organize issues.
* Add useful implementation notes.
* Track project tasks using GitHub Issues.
