# 13.5 Conflict Resolution

## About
This topic introduces Git conflict resolution. It focuses on understanding why conflicts happen during merge or rebase operations, inspecting conflicting files, resolving conflicts correctly, and validating the project after resolution.

## Concepts Covered
* Git merge conflicts
* Rebase conflicts
* Conflict inspection
* Conflict markers
* Resolving conflicts
* Staging resolved files
* Validation after resolution
* Completing merge or rebase

## What I Learned
* Conflicts can happen when different branches modify the same part of a file.
* Merge and rebase operations can both produce conflicts.
* Git uses conflict markers to show the conflicting sections.
* Conflicts should be inspected before making changes.
* The correct code or content should be selected and conflict markers removed.
* Resolved files must be staged after fixing the conflict.
* The project should be tested after resolving conflicts.
* Successful validation helps ensure that the resolution did not introduce new problems.

## Learning Outcomes

After completing this topic, I can:
* Understand why Git conflicts occur.
* Identify conflicts during merge and rebase.
* Inspect conflicting files and conflict markers.
* Resolve simple Git conflicts.
* Stage files after resolving conflicts.
* Validate the project after conflict resolution.
* Complete a merge or rebase successfully.
