# 4.5 Architecture

## About
This topic introduces the basic **architecture of a Streamlit application**. It explains how to separate the application into different layers such as the Streamlit page, service, domain or calculation layer, and repository.

## Concepts Covered

- Streamlit Page
- Service
- Domain / Calculation
- Repository
- Layer Separation

## What I Learned

- The Streamlit page handles the user interface and user interactions.
- The service layer handles application tasks and connects different parts of the application.
- The domain layer contains business logic and calculations.
- The repository handles storing and retrieving data.
- Separating these layers makes the application easier to understand, test, and maintain.
- Each layer should have a clear and specific responsibility.

## Learning Outcomes
After completing this topic, I can:

- Understand the basic architecture of a Streamlit application.
- Separate UI code from application logic.
- Understand the role of the service layer.
- Keep calculations and business logic in the domain layer.
- Separate data access using a repository.
- Build a cleaner and more maintainable Streamlit application.

## Architecture Flow
**Streamlit Page → Service → Domain / Calculation → Repository**
